@sandlada/document-context demo

Vanilla multi-page Vite demo. Each page imports the library with a bare specifier (@sandlada/document-context, @sandlada/document-context/domain) so Vite resolves the workspace link for dev, build, preview, and StackBlitz.

  • counter — state, update, subscribe$, select$, DOM render recipe
  • di — nested providers, ancestor inject, nearest-wins override
  • late-binding — inject before mount
  • persist — localStorage persistence plus serialize display
Published CDN equivalent (reference only, not executed here)

When the package is installed from a registry instead of the workspace, the same pages work with a real import map like this:

<script type="importmap">
{
    "imports": {
        "@sandlada/document-context": "https://esm.sh/@sandlada/document-context@0.1.0-alpha.0",
        "@sandlada/document-context/domain": "https://esm.sh/@sandlada/document-context@0.1.0-alpha.0/domain"
    }
}
</script>

This demo intentionally does not ship a live import map: a static map cannot point at workspace build output in a way that works for Vite dev, Vite build/preview, and StackBlitz at the same time, so the runnable scripts below use bare specifiers and let Vite resolve them.
